# Plan: v-312 (the evidence #312 still lacks)

## What is left

The latest verification comment on #312 marks one criterion met (one ignore
list, enforced by the `ci_workflows` tests) and two unshown:

1. "A pull request that adds a dependency with a known advisory fails the
   `Linux` job": only a local run shows it, no CI run.
2. "The nightly run reports a new advisory in the nightly issue": the
   `nightly-report` job has never run, because it runs only on `schedule`
   and no scheduled run has completed.

Neither can be shown by adding a vulnerable dependency to main. Both get a
dry run instead: a manual run of `Rust checks` with a new input that checks
a lockfile holding a known advisory, fails `Linux` on it, and goes through
the same `nightly-report` job.

## Changes

- `tests/fixtures/advisory-dry-run/known-advisory.lock` (new): a Cargo
  lockfile with one package, `smallvec 1.6.0` (RUSTSEC-2021-0003, patched in
  1.6.1). It is named `.lock`, not `Cargo.lock`, so GitHub's dependency graph
  and Dependabot don't read it as a dependency of this repository, and no
  manifest names it, so nothing builds it.
- `scripts/check.sh`: in the portable block, right after the real
  `cargo audit`, when `LANGSPAN_ADVISORY_DRY_RUN=1`, run the same command
  with the same ignore flags on the fixture:
  `cargo audit --deny warnings $audit_flags --file tests/fixtures/advisory-dry-run/known-advisory.lock`.
  The real lockfile is checked first, so the run shows it clean and then
  the gate failing. `set -e` ends the lane there, as a real advisory would.
- `.github/workflows/check.yml`:
  - `workflow_dispatch` input `advisory_dry_run` (boolean, default false).
  - env `LANGSPAN_ADVISORY_DRY_RUN: ${{ inputs.advisory_dry_run && '1' || '' }}`.
  - `nightly-report`: `if: (github.event_name == 'schedule' || inputs.advisory_dry_run) && failure()`,
    and a dry run reports under its own title ("Advisory dry run of the
    nightly report"), so it never opens or comments on the real "Nightly
    Rust checks on main failed" issue. The title stays fixed text from the
    workflow (no input text reaches `run:`), so zizmor's injection audit is
    unaffected and the job still runs no repository code.
- `tests/ci_workflows.rs`:
  - the dry-run input exists, defaults to false, and only it sets
    `LANGSPAN_ADVISORY_DRY_RUN`;
  - check.sh runs the dry-run audit after the real one with the same
    `$audit_flags`, and only under `LANGSPAN_ADVISORY_DRY_RUN=1`;
  - `nightly-report` runs for the schedule or the dry run, and the schedule
    keeps the title the coverage workflow shares (update the existing
    assertion in `coverage_runs_nightly_reports_a_drop_and_is_not_a_required_check`
    to the new expression, not weaken it);
  - the fixture is not named `Cargo.lock` and names `smallvec 1.6.0`.
- `docs/development-process.md`: one paragraph beside the nightly issue: how
  to run the dry run (`gh workflow run check.yml --ref BRANCH -f advisory_dry_run=true`)
  and what it shows.
- `docs/evidence/ci/advisories.md` (new) and a link from
  `docs/evidence/ci/README.md`: the dispatched run's URL, the `Linux` job's
  failing step and the advisory it names, the dry-run issue `nightly-report`
  opened (then closed), and the state of the scheduled nightly run.
