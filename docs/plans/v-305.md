# Plan for v-305: a prebuilt cargo-nextest with a pinned SHA-256 (#305)

## What is still open

The verification comment on #305 and the owner's amendment leave one gap:
`scripts/install-ci-tools.sh` builds cargo-nextest with `cargo install
--locked` (version-pinned only). It should download the upstream release
and check it against a pinned SHA-256 before unpacking, as cargo-deny and
cargo-machete already do. Every other criterion is met or amended
(macOS as a required check: owner decision on #487).

## Changes

1. `tests/ci_workflows.rs` (test first): a text test that the installer
   fetches cargo-nextest from `github.com/nextest-rs/nextest/releases`
   with a 64-hex digest for each pinned platform (Linux x86_64, macOS
   arm64), and no longer builds it (`build cargo-nextest` absent). Watch
   it fail on `main`'s script.
2. `scripts/install-ci-tools.sh`:
   - `nextest_sha` per platform, taken from the downloaded assets of
     `cargo-nextest-0.9.152` and checked against the digest GitHub records
     for each asset (`gh api .../releases/tags/cargo-nextest-0.9.152`).
   - nextest's tarball holds `cargo-nextest` at its root, not in a
     directory named after the asset, so `fetch` takes the path of the
     binary inside the archive (or a small variant for nextest); the
     digest check still runs before `tar`.
   - Always download and verify (seconds), so a binary restored from the
     build cache is replaced by the verified one instead of trusted.
   - Update the header comment; the unsupported-platform message names
     the nextest install line too.
   - cargo-audit and cargo-llvm-cov stay built: #305 asks only for
     nextest (cargo-audit is noted as not met by #477 but isn't a #305
     criterion; I list it as follow-up, not in scope).
3. Comment and doc text that says nextest is built, now inaccurate:
   - `docs/engineering.md` line 17 (CI installs cargo-deny, cargo-machete
     and cargo-nextest prebuilt; builds cargo-audit).
   - `.github/workflows/check.yml` comments only (time-limit comment,
     lines ~103–108); no step, path or key changes. `CACHE_PATHS` keeps
     the nextest path: changing that list empties every branch's cache and
     the file says to do it in a pull request of its own; it is pinned by
     `tests/ci_workflows.rs`.
   - `.github/workflows/coverage.yml` comment (line 29).
   - `docs/security/threat-model.md` CI build cache rows: nextest is now a
     verified download, so a cached copy is replaced, not run; a cold
     cache no longer builds it.
   - `docs/evidence/ci/pipeline.md` closing paragraph ("The cargo-nextest
     and cargo-audit builds remain…") to say nextest is now prebuilt.
