# v-360: a panic test for each moved daemon worker thread

Refs #360. The one unmet criterion (latest verification comment): "The panic
test from M2 still passes for each worker thread." Today only the owner
thread is panicked (`LANGSPAN_TEST_PANIC_ON_REQUEST`); nothing panics
`langspan-indexer`, `langspan-remote` or `langspan-hosts`.

The behaviour under test is the one #329 decided: a panic on any coordinator
thread stops the process with a failure status, removes its socket and
writes one `daemon_stopping` line naming the thread. (The task summary says
"stays up"; the issue and `stop_on_panic` say it stops. This plan follows the
issue.)

## Changes

1. `src/daemon/remote_worker.rs`: a debug-only `pub(super) fn
   panic_in_thread_for_test()`. When `LANGSPAN_TEST_PANIC_IN_THREAD` equals
   the current thread's name it panics; a release build compiles it to
   nothing and never reads the variable. Called as the first line of
   `host_worker` and `remote_worker`.
2. `src/daemon/index_worker.rs`: the same call as the first line of
   `index_worker`.
   - The helper does not go in `src/daemon.rs`: that file is held at its
     ratchet baseline (1,635 lines, `run` 366), and the calls go inside the
     moved worker functions, not the spawn closures in `run`, so the panic
     happens in the moved code.
3. `tests/coordinator_lifetime.rs`: split the spawn out of `start_with`
   (moves only) into `spawn_with`, since a worker that panics at entry can
   stop the coordinator before it first answers. One shared assertion
   helper and three tests, one per thread name, each asserting: the process
   exits within 10 s with a failure status, the socket is gone, the
   `daemon_stopping` line has `level: error`, `reason: panic`, `thread`
   equal to the named thread, and a `detail` naming the switch, and the
   default `panicked at` message is not written. Debug builds only, like
   the existing owner-thread test. These are process tests on purpose: what
   is verified is the process-wide panic hook, process exit and socket
   removal.

## Test-first order

1. Add the three tests; run them; they fail because the coordinator becomes
   ready and keeps running (nothing panics), so `exits_within` times out.
2. Add the helper and the three calls; the tests pass.
3. Break the guarded code once (stop `stop_on_panic` from exiting the
   process, so only the worker thread ends) and confirm all three tests fail;
   restore.

## Shared contracts touched

None: no protocol, CLI, golden or docs table change. A new debug-only
environment variable, like `LANGSPAN_TEST_PANIC_ON_REQUEST`. Ratchets:
`--check` after the change. If `index_worker` reaches the 150-line function
limit, it gets a recorded baseline.
