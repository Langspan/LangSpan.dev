## What changes

No product or test code. Each break below is made in the working tree, the
core's properties are run, the failing property and its output are copied
into this file and the pull request body, and the break is reverted by
hand before the next one. Nothing under
`crates/` is committed, and the `proptest-regressions/` file a failing run
writes is not committed (it records a case for a break that never
lands).

One break per property, so each property is shown to catch something:

| Property | Break (not committed) |
| --- | --- |
| `a_file_has_at_most_one_live_holder` | `conflicts` in `crates/langspan-core/src/admission.rs` returns no conflicts, so `decide` grants a second live lease on a held file (the break the comment suggests) |
| `a_repeated_request_id_keeps_the_first_answer` | `decide_admit` drops its `lease_id_reused` check, so a retry under the same ID is decided as a new admission |
| `apply_accepts_every_decided_event` | `decide_admit` emits a granted lease whose paths are not in canonical order, which `apply_lease_granted` refuses |
| `replaying_the_log_gives_the_same_state` | a field of the granted lease is skipped by serde, so the log read back from JSON folds to a different `State` |

If a break is caught by an earlier check than the property it targets (for
example `apply` refusing the reused lease ID), the record says so and names
the message, and a second break that reaches the property's own assertion is
tried.
