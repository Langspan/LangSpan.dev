## Causes found

**1. A signal between `Popen` and `RUNNING.append`.** `run_hook`
(`benchmarks/coordination/standin_agent.py:129-131`) starts the hook in its
own group, then appends it to `RUNNING`. Python runs a signal handler at
the next bytecode, which can still be inside `Popen` once the child has
exec'd. Under load the hook can write its group file and heartbeat in that
window; the test then signals, `stop_on_signal` finds `RUNNING` empty, and
the stand-in dies without ending the hook's group. Its loop runs forever,
which matches "group 35451 still runs [35451, 37778]" (sh plus its `sleep`).
The `hook-log` wrapper already defers a signal that arrives while its hook
starts (`driver.py:845-860`). The stand-in does not.

**2. The bound expires before the wrapper starts the hook.** The test sets
`HOOK_SECONDS = 0.5`. Behind `hook-log`, a Python interpreter has to start
and import `driver.py` before the hook's shell runs. On a loaded Mac that
takes longer than 0.5 s, so the stand-in ends the wrapper before any
heartbeat exists. The product behaved correctly; the test's precondition
("the hook's child ran") wasn't met.

**4. A delivering briefing is recorded as told before the hook receives it
(both hangs).** `Brief { deliver: true }` appends `BriefingDelivered` with
the told keys when the core decides it (`crates/langspan-core/src/briefing.rs`
`decide_brief`). The hook waits for the reply within its 1.5 s budget
(`src/hook.rs:102`). When the budget runs out first, the hook returns with no
context (`src/hook.rs:1131`, `:2446` `.ok()?`). `forget_unplaced` runs only on
success, so the keys stay told. Later briefings use `changes_only` and skip
them, so the notice is lost for good. The rename test then polls for 60 s.
The dry run's following stand-in waits until about 570 s (`--time-limit 600`
less the 30 s margin), past nextest's 480 s. This is a product bug: under
load, a session can be marked informed without being told.

## This pull request (slice 1): causes 1 and 2, and the Linux evidence

Test first, each change in order:

1. `test_driver.py`, new test in `StandinHooks`:
   `test_a_signal_while_the_hook_starts_still_ends_its_group`. A process
   test, because signal delivery and process groups are the OS behavior
   under test. A child Python imports `standin_agent`, wraps
   `subprocess.Popen` so that it sends the process SIGTERM right after the
   real `Popen` returns (before `RUNNING.append`), installs the stand-in's
   handlers and calls `run_hook` with the heartbeat loop. The test waits for
   the child to die of SIGTERM, then uses `assert_stopped` on the hook's
   group. Watch it fail on the current code with "still runs".
2. `standin_agent.py`: make the hook's start a critical section, as
   `hook-log` does. A module-level `STARTING` flag and a `PENDING` list:
   `stop_on_signal` records the signal while a hook is starting and returns.
   `run_hook` clears the flag after `RUNNING.append` (in a `finally`, so a
   failed `Popen` still honors it) and then handles any pending signal.
   Signals aren't blocked with `pthread_sigmask`, because the hook would
   inherit the blocked mask through exec and ignore SIGTERM. The new test
   passes; break the fix once (drop the pending replay) and confirm it fails.
3. `test_driver.py`, the sibling test: when the bound expired before the
   hook's child ran (no group file or no heartbeat), that attempt didn't
   test the bound. Run it again with the bound doubled (0.5, 1, 2, 4, 8,
   16 s), and fail with a clear message if even 16 s isn't enough. Each
   attempt that did run still gets the full `assert_stopped` check. No
   assertion is weakened, and an unloaded run still takes 0.5 s.
4. Evidence on Linux: in a Linux container (Docker via OrbStack on this Mac;
   needs the owner's approval to run `docker`), `python:3` plus `procps` and
   `stress-ng --cpu $(nproc)`, run
   `python3 -I -B -m unittest test_driver.StandinHooks` 200 times in a row
   and stop at the first failure. Do the same 200 times on macOS under
   `yes > /dev/null` on every core. Record the commands, CPU count, Python
   version and counts in the PR body. Also run once against the unfixed
   `standin_agent.py` under the same load, to show the loop finds the race.
5. `cargo fmt`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
   the full `cargo nextest run --workspace --locked`, then the PR.
