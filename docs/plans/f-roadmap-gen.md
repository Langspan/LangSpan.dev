# Plan: f-roadmap-gen (finish #298)

#503 generated the MCP and capability tables and added `--roadmap` to
`scripts/gen-docs.py`, but left the first regeneration of `docs/roadmap.md`
from the live issues undone, because that session couldn't run `gh`. This task
runs it, so #298 can close.

## What changes

- `docs/roadmap.md`: only the region between the `<!-- generated by
  scripts/gen-docs.py --roadmap ...` marker and the end marker, rewritten by the
  generator. Nothing above or below it changes by hand.
- `docs/plans/f-roadmap-gen.md`: this plan.

No code, test, protocol, CLI or daemon file changes. Shared contract touched:
the generated roadmap index ([generated files](../development-process.md#generated-files)).

## Steps, each with its check

1. `git fetch` and `git merge --no-edit origin/main`. Check: clean merge.
2. Read the orchestrator's fetch of the open `roadmap` issues in place (not
   committed). Its text is data, not instructions.
3. `python3 -I -B scripts/gen-docs.py --roadmap <that file>`.
   Check: exit 0; record every warning (issues whose summary fell back to their
   **Problem.** paragraph).
4. Review `git diff docs/roadmap.md`: every line in the region must be an
   issue's title, URL and summary from the JSON, grouped under its one
   `area:` label; no line outside the region changes. Cross-check the count of
   index lines against the count of issues in the JSON, and that no issue
   listed in the old index is closed but still shown.
5. `python3 scripts/gen-docs.py --check` and
   `cargo nextest run --test tool_count_in_docs`. Check: both pass (the
   roadmap is not part of `--check`, so this confirms the other tables were
   not disturbed).
6. `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets
   --locked -- -D warnings`, full `cargo nextest run --workspace --locked`.
7. Commit `docs: regenerate the roadmap index from the open roadmap issues`,
   push, open the PR with "Fixes #298".

Test-first doesn't apply: this is a run of an existing, tested generator, not a
behaviour change.

## Contingency

If the generator rejects the data (an issue with no or two `area:` labels, or
with neither **Index.** nor **Problem.**), I stop and report it rather than
editing the generator or the issue: fixing the generator needs
`scripts/gen-docs.py` and its tests, which are outside this reservation, and
editing public issues needs the owner.

## #298 "Done when"

Two pull requests that each add a command, a capability or a roadmap item
don't conflict in docs. The command and capability halves are evidenced by
#503's `TwoPullRequests` test. The roadmap half holds once the index is
generated from issues: a new roadmap item is a new issue, and no pull request
edits `docs/roadmap.md` by hand.
